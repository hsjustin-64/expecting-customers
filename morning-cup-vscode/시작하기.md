# 모닝컵 V2 — 우리 상권과 내일의 손님

서울시 상권 혼잡도와 주고객층을 확인하고 매장 전체 방문객 수 또는 결제 건수의 내일 경향을 예측합니다. 기존 메뉴·재료·재고·발주 화면은 제거했습니다.

## 바로 체험

Windows x64 / Python 3.10~3.12(64비트)에서:

1. ZIP을 풀고 이 폴더를 VS Code로 엽니다.
2. 최초 한 번 install.bat를 실행합니다. 인터넷이 필요하며 실제 Prophet 검사까지 통과해야 완료됩니다.
3. start.bat를 실행하면 http://127.0.0.1:8765 에서 앱이 열립니다.
4. 대학가 카페 / 오피스 음식점 / 주거지역 카페 중 선택하고 '내일 수요 계산하기'를 누릅니다.

API 키 없이 시연 모드를 사용할 수 있습니다. 세 매장에 각각 180일의 가상 영업·인구·날씨 이력을 생성하고 실제 Prophet으로 학습합니다. 모든 시연 데이터는 화면과 CSV에 synthetic / 시연용 가상 데이터로 표시합니다. 실제 매장 정확도를 입증하는 결과가 아닙니다.

## VS Code Live Server

Python, Python Debugger, Live Server 확장을 설치합니다. F5 또는 start-backend.bat로 Python 서버를 먼저 실행하고, 최상단 index.html을 Open with Live Server로 여세요. 포트는 5500, 호스트는 127.0.0.1입니다. 두 서버를 함께 실행해야 합니다. 다른 앱이 포트를 사용하면 기존 서버를 종료하세요. Live Server만으로 Prophet은 실행되지 않습니다.

Python 환경은 Windows 긴 경로 제한을 피하도록 LocalAppData/MCup 아래에 설치됩니다. install.py가 .python-path 및 VS Code 설정을 갱신합니다. 다른 PC로 복사한 경우 install.bat를 다시 실행하세요. 한글 사용자 경로의 Stan CSV 오류 호환 처리도 포함했습니다.

## 실제 매장 / API 설정

.env.example을 .env로 복사하여 SEOUL_API_KEY, OPENWEATHER_API_KEY를 입력하고 Python 서버를 재시작합니다. 키는 브라우저에 반환하지 않습니다. .env는 공유 ZIP이나 저장소에 넣지 마세요.

- 서울시: https://data.seoul.go.kr/dataList/OA-21778/A/1/datasetView.do
- 구역 확인: https://data.seoul.go.kr/dataVisual/seoul/guide.do
- OpenWeatherMap 5-day / 3-hour forecast: https://openweathermap.org/api/forecast5

실제 모드에서 '인구·날씨 정보 갱신'을 눌러 조회합니다. 서울시 주소는 공식 샘플 호출로 확인한 http://openapi.seoul.go.kr:8088 입니다. 이 상류 API는 HTTP를 사용합니다. 앱의 공개 웹사이트는 Railway HTTPS로 제공되며 키는 서버에서만 보관합니다.

매장 위치는 서울시 자치구·동·상세 위치와 위경도를 입력합니다. 위경도는 날씨 조회용으로 반드시 실제 매장 좌표를 확인하세요. 서울시 API 제공 구역명을 공식 목록에서 선택·입력하고 매장과의 연관성을 확인합니다. 임의의 동 이름과 제공 구역을 동일하게 취급하지 않습니다. 이번 버전은 좌표 지오코딩/자동 구역 매칭은 하지 않습니다.

공식 인구 응답의 10세 미만 + 10대 비율은 화면의 '10대 이하'로 합산합니다. 다른 연령대는 각각 표시합니다. 여성 비율과 20대 비율을 곱해 '20대 여성 인구'라고 표시하지 않습니다.

실제 기록은 ds,y 필수 열, valid,is_closed 선택 열의 UTF-8 CSV입니다. 하루 한 행, 어제까지의 기록, 정수 건수를 사용합니다. 업로드는 기존 이력을 전체 교체하며 화면에서 확인합니다. demo CSV는 실제 모드에 업로드되지 않습니다. 메뉴별 CSV와는 구조가 다릅니다.

## 예측 규칙

- 42개 이상 유효 영업일: Prophet / 주간 계절성 / 한국 공휴일.
- 주고객 성별 및 연령대에 해당하는 별도 인구 비율 변수를 선택합니다. 내일 인구는 이력의 최근 같은 요일 최대 4회 평균으로 추정합니다. 현재 실시간 인구를 내일 실제 인구로 대입하지 않습니다.
- 날씨/인구 선택 이력 열: temp, rain, pop, female, age_10~age_70. 과거 이력이 완전하고 값에 변화가 있을 때만 해당 변수 학습. 날씨는 내일 예보도 필요합니다. 강수확률은 화면 안내용이며 현재 모델에는 기온·강수량을 반영합니다.
- 인구·날씨 갱신 이력은 저장합니다. 인구는 한 시간당 한 관측을 쓰며 영업시간의 75% 이상, 최소 3시간이 수집된 날짜만 일별 집계를 학습에 보충합니다. 날씨는 전날 조회한 대상일 예보를 기록합니다. 자동 백그라운드 수집기는 없으며 갱신 버튼을 사용할 때 수집합니다.
- 상권 일정은 확인 기간이 학습 이력과 내일을 포함하고 해당/비해당 이력이 충분한 경우 반영합니다.
- 데이터 부족·모델 오류: 같은 요일 최근 4주 평균, 없으면 최근 14개 유효 영업일 평균. 이를 모델 예측으로 표시하지 않습니다.
- 유효 기록이 없을 때만 판단 보류. 예정 휴무는 0으로 안내합니다.
- Prophet 예상값이 비교 평균 대비 +10% 초과면 증가, -10% 미만이면 감소, 그 사이는 평소 수준. 비교 기준이 0이면 변화율 대신 건수 제공.
- 넓은 예측 범위만으로 판단을 보류하지 않습니다. 80% 모델 설정 구간은 실측 포함률이나 정확도 보장이 아닙니다.
- 검증 화면은 과거 예보를 가정하지 않는 달력 기반 최대 7일 순차 비교입니다. 외부 변수 추가 효과를 입증하는 검증은 별도 과제입니다.

## 저장과 기존 버전

V2는 data/demand-v2.db를 사용합니다. 기존 data/shop.db는 읽거나 변경하지 않습니다. 로컬은 프로그램 폴더별 독립 매장입니다. 공개 모드는 브라우저 세션별로 매장을 분리하며 7일간 미사용한 매장 데이터는 다음 저장 시 정리합니다. 계정 서비스가 아니므로 브라우저 쿠키를 지우면 공개 모드의 이전 매장에 다시 접근하지 못할 수 있습니다.

## Railway 배포 준비

Dockerfile과 railway.json을 포함했습니다. 코드만 수정한 상태이며 실제 배포 링크는 아직 생성되지 않았습니다.

1. 이 폴더를 저장소에 올리되 .env, .python-path, data, .venv는 제외합니다.
2. Railway에서 저장소로 새 서비스를 생성합니다.
3. 환경변수 PUBLIC_DEMO=1, SECRET_KEY=충분히 긴 임의 문자열(32자 이상)을 설정합니다. API 키도 환경변수로 설정합니다.
4. 볼륨을 /data에 연결하고 DATA_DIR=/data를 설정합니다. 저장 공간이 없으면 재시작·재배포 시 데이터가 사라질 수 있습니다.
5. Generate Domain으로 HTTPS 주소를 만들고 /health와 실제 예측 버튼을 확인합니다. 서버는 Railway PORT를 사용합니다.
6. 10월 6일까지 요금제·사용량·운영 기간을 유지합니다. Docker 빌드 및 실제 Railway 운영은 아직 검증하지 않았습니다.
