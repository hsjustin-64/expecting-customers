# 모닝컵 — 작은 카페의 내일 준비

샌드위치·베이글 카페를 위한 로컬 실행 프로그램입니다. 실제 Prophet으로 내일 품목 판매량을 예측하고, 레시피와 재고를 연결해 발주 초안을 만듭니다.

## 실행

Windows x64 / Python 3.10~3.12(64비트)에서 `install.bat`를 실행하세요. 각 컴퓨터에 가상환경과 실제 Prophet을 새로 설치합니다. 최초 설치에는 인터넷이 필요합니다. VS Code Live Server 실행 방법은 [시작하기.md](시작하기.md)를 보세요.

## 사용 순서

1. **첫 화면**: 내 매장으로 시작하거나 샘플 체험을 선택합니다. 내 매장은 메뉴·재료·레시피와 실제 판매 CSV를 등록한 후 예측합니다. **내일 준비**에서 내일의 영업시간 기온·강수 예보, 예보 발표 시각, 영업시간, 할인율, 예약 주문을 넣고 계산합니다.
2. **매장 설정**: 가격과 메뉴별 여유 수량을 수정합니다. 전체 설정 편집에서 메뉴·재료·레시피·납기·마감 시각을 변경할 수 있습니다.
3. **재고 · 발주**: 실물 재고, 오늘 남은 시간의 사용량, 사용기한, 입고 예정량을 저장합니다. 내일 예측을 다시 실행한 다음 발주 묶음 수를 검토·수정하고 초안을 저장합니다. CSV로 내려받을 수 있습니다. 거래처로 전송하지 않습니다.
4. **판매 · 예측 확인**: CSV 양식을 내려받고 일별·메뉴별로 작성합니다. 업로드는 기존 판매 이력 전체를 교체합니다. 실제 데이터를 쓰려면 먼저 매장 설정에서 실제 매장으로 전환하세요.
5. **마감 기록**: 남은 완제품, 폐기, 품절 시간을 기록합니다. 판매 이력이 있는 날짜의 품절 시간은 학습 제외에 반영됩니다. 마감 입력은 판매 수량 자체를 생성하지 않습니다.

샘플에서 실제 매장으로 전환하면 가상 판매·마감 기록과 재고를 초기화합니다. 메뉴·레시피는 편집용 틀로 유지되므로 실제 매장에 맞게 확인하세요.

## 예측과 데이터 정의

### 상권 선택과 지역 일정

매장 설정 첫 단계에서 대학가 / 오피스 / 주거 / 관광·나들이 / 복합·기타를 선택합니다. 상권 이름에 고정 가중치를 주지 않고 다음 날짜별 변수를 추가합니다.

| 상권 | 추가 변수 |
|---|---|
| 대학가 | 학기 중, 시험 기간, 주변 축제·행사 |
| 오피스 | 주변 회사 휴무·출근 감소 기간, 주변 행사 |
| 주거 | 초·중·고 방학, 주변 행사 |
| 관광·나들이 | 지역 관광 성수기, 주변 행사 |
| 복합·기타 | 주변 행사 |

요일·한국 공휴일·날씨는 공통으로 사용하며, 메뉴별 매장 데이터로 계수를 학습합니다. 오피스의 평상시 주말·공휴일은 공통 달력에 맡기고 특이 휴무·출근 감소 기간만 별도로 등록합니다. 일별 모델이므로 점심시간 피크는 아직 구분하지 않습니다.

1. 관련 대학·회사·지역 이름을 선택적으로 입력합니다. 자동 위치 분석은 하지 않습니다.
2. 과거 판매 이력부터 내일 이후까지 일정을 확인한 기간을 지정합니다.
3. 학기·시험 등 실제 시작일과 종료일을 등록합니다. 같은 종류의 기간을 여러 개 입력할 수 있습니다. 시작·종료일은 모두 포함됩니다.
4. 확인 기간 안의 관련 일정을 빠짐없이 확인했다는 항목을 체크하고 저장합니다. 기간 밖은 미확인으로 취급하며 자동으로 방학·비수기로 간주하지 않습니다.
5. 내일 준비량을 다시 계산하면 메뉴별 변수 반영/제외 이유가 표시됩니다.

유효 이력 전체와 내일이 일정 확인 기간 안에 있어야 합니다. 최소 42개 유효 관측과, 해당 기간/그 외 기간 각각 최소 7개 유효 관측이 필요합니다. 동일한 이진 패턴의 상권 변수는 하나만 사용합니다. 이 기준은 초기 과적합 억제용 사용 조건이며 인과효과나 성능 개선을 보장하지 않습니다. 학기와 계절 등이 함께 바뀌는 경우 효과를 구별하기 어려울 수 있습니다. 상권 추가 회귀변수의 prior_scale은 초기값 2.0입니다.

미확인 일정이나 충분한 이력이 없는 변수는 제외하고 기본 예측을 유지합니다. 현재 저장된 일정의 과거 변경 이력을 보존하지 않으므로 순차 검증 화면에서는 상권 변수를 제외합니다. 향후 당시 알려진 일정의 버전을 수집해야 상권 모델의 운영 성능을 공정하게 비교할 수 있습니다.

- 한 매장, 한 메뉴, 하루 판매 수량을 모델 단위로 사용합니다. 전날 오후에 예측하므로 오늘 진행 중인 판매는 학습하지 않습니다.
- `y`는 예약을 포함한 총 판매 수량, `confirmed_order_qty`는 그중 예약 판매 수량입니다. 과거 예약을 빼고 학습한 뒤 내일 확정 예약을 더합니다. 과거 예약을 분리할 수 없다면 미래 예약 추가를 사용하지 마세요.
- 휴무, 품절 시간이 1분 이상인 날, 수집 오류, 미판매 메뉴인 날은 제외합니다. 없는 날짜를 판매 0으로 채우지 않습니다. 품절일 제외도 선택 편향을 만들 수 있으며, 잃어버린 수요를 복원하지는 않습니다.
- 유효 이력 42일 이상: 선형 추세 + 주간 계절성 + 한국 공휴일의 Prophet. 일중·연간 계절성은 끕니다. 과거 열이 있고 값이 변하는 기온·강수·영업시간·할인율만 추가합니다.
- 14~41일: 최근 같은 요일 최대 4회 평균. 해당 요일 기록이 없으면 최근 14개 유효 관측 평균. 14일 미만이면 예측을 중단하고 이유를 표시합니다.
- 참고 범위: Prophet의 기본 80% 설정 산출 구간을 0 이상으로 제한합니다. 실제 포함률 검증 전이므로 보장된 80% 범위라고 표시하지 않습니다. 기준 모델은 최근 28개 유효 관측의 표준편차를 이용한 참고 폭입니다.
- 과거 검증은 최근 유효일 최대 7일을 순차 평가하고 매 평가일 전날도 학습에서 제외합니다. 과거 예보가 없으므로 날씨를 제외한 Prophet과 같은 요일 평균의 MAE만 비교합니다.
- 기온·강수는 수동 예보 입력입니다. 발표 시각을 저장하고 미래 발표 시각은 거부합니다. 예보 API·유동인구 API·POS 자동 수집은 연결되지 않았습니다.

## 재고 계산

`준비량 = 올림(일반 판매 예상 + 확정 예약 + 메뉴별 여유 수량)`

`재료 필요량 = 메뉴별 준비량 × 메뉴 1개당 재료 사용량의 합`

`사용 가능 재고 = max(0, 내일 유효한 현재 재고 − 오늘 추가 사용량)`

`발주 묶음 = 올림(max(0, 필요량 − 사용 가능 재고 − 내일 유효한 입고량) / 묶음 크기)`

재료는 한 레코드당 하나의 재고 사용기한과 하나의 입고 건을 관리합니다. 사용기한이 다른 로트, 복수 입고·다일 배분·FEFO는 아직 지원하지 않습니다. 기한 지난 재고는 내일 소요에서 제외합니다. 묶음 발주 후 예상 잔량을 표시합니다. 납기는 달력 일수로 계산하고 발주 마감 이후에는 1일을 추가합니다. 주말·거래처 휴일은 별도 처리하지 않습니다.

발주는 **내일 하루 부족분**만 계산합니다. 늦게 도착하는 발주는 대체 조달 경고를 표시하며 장기 납기 주문 최적화를 수행하지 않습니다. 초안 저장은 실제 입고 예정량을 늘리지 않습니다. 실제 주문을 넣은 후 재고 화면에서 입고 정보를 입력하세요.

## 저장 및 운영 범위

- 데이터: `data/shop.db` (SQLite). 앱을 종료하고 이 파일을 복사하면 백업할 수 있습니다.
- 예측·재고·설정 변경으로 이전 발주 초안을 무효화하여 오래된 수량의 재사용을 줄입니다.
- 단일 사용자 로컬 MVP입니다. 인터넷 공개 서버, 여러 매장, 계정·권한 관리, 동시 접속용 배포는 포함하지 않습니다.
- LightGBM, 시간대별 추가 준비, 직원 근무 최적화, 생성형 AI 채팅은 후속 범위입니다. 참조 대화의 마지막 결정에 맞춰 Prophet과 다음 날 준비·발주에 집중했습니다.

## 개발 및 검증

```
.venv\Scripts\python.exe tests.py
.venv\Scripts\python.exe -m pip check
```

`app.py`: 로컬 API·SQLite·CSV·샘플 데이터

`engine.py`: 판매 검증·Prophet·기준 모델·순차 검증·발주 계산

`static/`: 한국어 반응형 화면
